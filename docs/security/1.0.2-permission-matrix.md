# 1.0.2 Edge Function permission matrix

Plan §7-I step 1. One row per resource × function × action that an Edge Function touches. Written before any client swap (task I1, 2026-09-24).

**Clients**
- **user**: `createClient(SUPABASE_URL, SUPABASE_ANON_KEY, { global: { headers: { Authorization: 'Bearer <caller JWT>' } } })`. The `authenticated` role; grants and RLS apply.
- **service**: `SUPABASE_SERVICE_ROLE_KEY`. The `service_role` role (BYPASSRLS). Allowed only for trusted, server-derived state that clients must not write, and always pinned to the verified caller id.

**Citations** use `supabase/migrations/<file>:<line>` and `supabase/functions/<fn>/index.ts:<line>`, based on HEAD 54ecb24 plus I1. Tables whose grants come from Supabase's default ACL, with no explicit GRANT in a repo migration, are marked `default ACL (UNKNOWN line)`. Verify those against the live database before relying on them.

**Status** values: `DONE (<task>)` means the target client is in the code. `KEEP` means the service client stays, with the reason given. `FOLLOW-UP (<task>)` means the target is agreed but the code is not changed yet. `NONE` means there is no direct access and none should be added.

## Notes for later tasks

- **I2 (coach / meal-plan trusted writes):** DF-07 and MP-05 stay on the service client. Move the reads marked `FOLLOW-UP (I2)` to the user client, keeping the `.eq('user_id', verified)` pinning. MP-02 first needs `GRANT EXECUTE ... read_meal_plan(uuid) TO authenticated` plus an `auth.uid()` pin in SQL, as `read_nutrition_target_set` already has.
- **G11a (delete-account):** after `20260924000100`, service_role has **no** INSERT/UPDATE/DELETE/TRUNCATE on `nutrition_target_sets` or `nutrition_target_day_overrides`. Do not delete those rows directly with the service client. Both tables have `user_id ... REFERENCES auth.users(id) ON DELETE CASCADE` (`0047:16`, `:68`), so `auth.admin.deleteUser` removes them through the FK cascade, which runs with the table owner's rights. So do `body_metrics`, `body_photos` and `resting_heart_rate` (`0036:11`, `:62`, `:98`). Storage objects under `<uid>/` are **not** cascaded. Remove them explicitly before deleting the user.
- **Appending:** add rows with the next free ID in the resource's prefix (for example `DA-01` for delete-account). Fill every column, and cite only lines you have read.
