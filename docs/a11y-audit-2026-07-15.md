# WCAG 2.2 AA Audit & Remediation — coachkettle.com

**Version:** 1.0
**Date:** 2026-07-15
**Auditor:** engineering (self-assessment)
**Standard:** WCAG 2.2 Level AA
**Scope:** coachkettle.com marketing site — 5 routes (`/`, `/guide`, `/privacy`, `/support`, `/eula`), 8 components, 5 pages. Vite + React 18 + Tailwind 3, `HashRouter`, deployed to GitHub Pages from `landing-page`.
**Baseline commit:** `b35d05b`

**Statement, palette, and manual-testing gaps:** `ACCESSIBILITY.md`.

## Order of work

Remediated in legal-exposure order — core conversion flow first, then severity — not file order.

The conversion flow here is **`/` → App Store** (there is no cart or checkout; the site's single conversion is the App Store link, with `mailto:` support as secondary). `Hero.tsx`, `Navbar.tsx` and `AppStoreBadge.tsx` were therefore taken first, and five of the twelve commits touch the homepage.

## Findings & fixes

Sorted BLOCKER → MAJOR → MINOR. Line numbers are against baseline `b35d05b`.

### BLOCKER — a disabled user could not complete a core task

#### 1. SC 2.2.2 Pause, Stop, Hide — Level A
| | |
|---|---|
| **Where** | `src/index.css:49–164` (10 `@keyframes`, applied across `Hero.tsx`, `CTA.tsx`, `Features.tsx`) |
| **Failed** | `float`, `float-slow`, `float-drift`, `twinkle`, `pulse-ring`, `spin-slow`, `bounce-subtle`, `blink`, `shimmer`, `border-glow` — all auto-start, loop infinitely, run in parallel with content. No mechanism to pause, stop, or hide. No `prefers-reduced-motion` guard anywhere in the codebase. |
| **User impact** | Vestibular disorder trigger. ~35 simultaneously animating elements on the homepage. A user with vestibular sensitivity could be made nauseated or unable to use the page at all. This is the one finding on the site capable of causing physical harm. |
| **Fix** | `@media (prefers-reduced-motion: reduce)` holding every animation at one frame; `scroll-behavior: auto`. Entrance animations and all three IntersectionObserver reveals pinned to their finished state — otherwise suppressing motion strands content at `opacity: 0`, which is a worse bug than the original. |
| **Evidence** | Playwright with `reducedMotion: "reduce"`: asserts no element retains a running animation **and** that the `h1` and both hero CTAs remain visible. Media query confirmed to survive minification in `dist`. |
| **Commit** | `dbf61e1` |

#### 2. SC 2.1.1 Keyboard — Level A
| | |
|---|---|
| **Where** | `src/pages/Privacy.tsx:157`, `src/components/Tutorial.tsx:104` (×3) |
| **Failed** | Four `overflow-x-auto` containers scroll horizontally at narrow widths while holding no focusable content. |
| **User impact** | **Only reproducible at 320px — the desktop pass missed it entirely.** On `/privacy`, the GDPR table's third column, *"Legal Basis (GDPR)"*, sat outside the viewport with no keyboard route to it: a keyboard-only user could not read the legal basis on which their own data is processed. A mouse user could drag it into view. On `/guide`, the end of every code example was unreachable. |
| **Fix** | `tabIndex={0}` making the region focusable and arrow-scrollable. Privacy table also gains `role="region"` + `aria-label`; Tutorial boxes gain `role="group"` (not `region` — 11 extra landmarks on `/guide` would be worse than none). |
| **Evidence** | axe `scrollable-region-focusable` clears on both routes at 320px. |
| **Commit** | `02f4179` |

### MAJOR

#### 3. SC 1.1.1 Non-text Content — Level A
| | |
|---|---|
| **Where** | `src/components/Hero.tsx:104` (wrapper), `:218`, `:246`; `src/pages/Support.tsx:12`, `:29`, `:39`; `src/components/Tutorial.tsx:106`; `src/components/AppStoreBadge.tsx:10` |
| **Failed** | The hero's entire decorative layer was exposed to assistive tech: 14 floating stat labels, 8 sparkle SVGs, 5 hand-drawn kettlebell SVGs. `Support.tsx`'s `QIcon` sat **inside** every FAQ `<h3>`. |
| **User impact** | A screen reader announced *"BENCH 225×8, SQUAT 315×5, DEADLIFT 405×3, PR!, 3×10 ROWS…"* as page content **before reaching the headline**. On `/support`, every FAQ heading announced as *"Q How do I delete my account and data?"*, corrupting the heading list — the primary way screen-reader users scan a long FAQ. |
| **Fix** | `aria-hidden` on the hero decorative wrapper (covers labels, sparkles, kettlebells, rings, watermark in one attribute), the `h1` underline scribble, the scroll arrow, `QIcon`, both tip SVGs, the `>` prompt glyph, and the Apple logo. |
| **Scope correction** | `lucide-react` **already** applies `aria-hidden` to childless icons (`Icon.mjs:36`). The floating gym icons were never exposed. An initial fix here was redundant and was reverted rather than left in to pad the diff. |
| **Evidence** | `aria-hidden` count in `dist` = 12 = 11 from `src` + 1 from lucide's shared component. Reconciled exactly. |
| **Commit** | `e09cd48` |

#### 4. SC 2.4.1 Bypass Blocks — Level A
| | |
|---|---|
| **Where** | `src/App.tsx:12` |
| **Failed** | No skip link. `<main>` had no `id` and was not focusable. |
| **User impact** | Keyboard and screen-reader users traversed the full navbar on all five routes, every page load, with no way past it. |
| **Fix** | Skip link as first focusable element, revealed on focus via `transform` (kept in tab order, not `display:none`). `<main id="main" tabIndex={-1} className="scroll-mt-24">`; link at `z-index:100` above the `z-50` navbar so it cannot be obscured on reveal (SC 2.4.11). |
| **Evidence** | Playwright presses `Tab` once, asserts the skip link is focused **and in viewport**, presses `Enter`, asserts `document.activeElement.id === "main"`. |
| **Commit** | `6e34341` |

#### 5. SC 1.3.1 Info and Relationships — Level A
| | |
|---|---|
| **Where** | `src/pages/Support.tsx:86, 163, 224, 282, 251`; `src/pages/Guide.tsx`; 12 lists across `Navbar`/`Support`/`Privacy` |
| **Failed** | Three distinct defects: (a) Support's four section labels were styled as headings but marked `<p>`, leaving `h1 → h3` with no `h2`, plus a stray `h4`; (b) `/guide` had **no `h1` at all**; (c) Tailwind preflight emits `ol,ul,menu{list-style:none}` — confirmed in `dist` CSS — and Safari/VoiceOver drops list semantics from any list styled that way. |
| **User impact** | Support's section structure was invisible to heading navigation. `/guide` had no page title in the heading tree. *"5 known limitations"* never announced as a list of 5 in VoiceOver — the pairing that matters most for an iOS product's site. |
| **Fix** | Section labels → `<h2>`, tips `<h4>` → `<h3>`. Tutorial's `<h2>` → `<h1>` and step `<h3>` → `<h2>` (Tutorial is `/guide`'s sole content and is imported by no other route). `role="list"` on all 12 lists. All styling unchanged. |
| **Evidence** | Playwright asserts exactly one `h1` per route and no level skips, across all 5 routes. |
| **Commit** | `2347482` |

#### 6. SC 4.1.2 Name, Role, Value — Level A · and SC 1.4.1 Use of Colour — Level A
| | |
|---|---|
| **Where** | `src/components/Navbar.tsx:6–11, 24–71, 67–83` |
| **Failed** | None of the 7 nav links exposed selected state. The mobile nav marked the current page by **lightness alone** (`#9a9a9a` → `#f0f0f0`). |
| **User impact** | A screen-reader user could not tell which of Home/Guide/Privacy/Support they were on — all seven links announced identically. |
| **Fix** | `aria-current="page"` on the active link in both navs, `undefined` when inactive so the attribute is absent rather than `aria-current="false"`. Underline added as a redundant non-colour channel on mobile. The desktop pill nav already varied its background, so colour was never its sole indicator there. |
| **Evidence** | 7 bindings in `src`, 7 in `dist`; Playwright asserts `nav a[aria-current="page"][href="#/guide"]` resolves per route. |
| **Commit** | `c421d17` |

#### 7. SC 1.4.3 Contrast (Minimum) — Level AA
| | |
|---|---|
| **Where** | `Hero.tsx:206, 245, 148`; `Tutorial.tsx:170, 79`; `Features.tsx:118`; `AppStoreBadge.tsx:21` |
| **Failed** | Seven text elements, worst at **1.16:1**. Full before/after table with computed ratios in `ACCESSIBILITY.md` §3.1. |
| **User impact** | Unreadable for low-vision users, and for anyone on a phone in gym lighting — the site's actual audience. |
| **Fix** | Opacity corrections only; the seven brand tokens are untouched. Two of seven reuse the existing `brand-muted` token rather than introducing a new value. |
| **Judgement call, owner-decided** | The 14 hero labels at 1.16:1 qualified for SC 1.4.3's *pure decoration* exemption (aria-hidden, no information conveyed, retained not removed). The standing recommendation was to invoke it and keep the hero pixel-identical. **The owner elected to make them pass outright** rather than rely on an exemption argument — `white/50`, 5.31:1. This is a deliberate, approved visual change: the labels are now legible rather than near-invisible. |
| **Evidence** | Ratios computed against composited backgrounds, not estimated. `white/45` = `#767676` = **4.46:1** and fails 4.5:1 by 0.04 — which is precisely why. axe confirms 0 contrast violations at both viewports. |

### MINOR

#### 8. SC 2.5.8 Target Size (Minimum) — Level AA
| | |
|---|---|
| **Where** | `Navbar.tsx:15, 67`; `Footer.tsx:17–40`; 16 links across all 4 pages; `Eula.tsx:41` |
| **Failed** | Measured in Chromium: navbar brand **87×22**, mobile nav **20.5px**, footer **19.2px**, page links **22.4px**, Eula's Apple link **127×20**. `body` `line-height: 1.6` on small type put every one under 24px. |
| **User impact** | Difficult to hit for users with motor impairments or tremor. |
| **Fix** | `inline-flex` + `py-2`. Navbar links add `-my-2` to preserve header height; page links deliberately do **not**, because eight carry `mb-10` and a negative block margin would collide with it. |
| **Note** | The 2.5.8 spacing exception was **not** relied on. Bottom link groups use `gap-y-2` (8px), so any wrap — exactly what happens at 320px or under the 1.4.12 text-spacing overrides — would collapse it. Meeting the size minimum outright is not conditional on layout. |
| **Evidence** | Playwright measures every rendered `a[href]` on all 5 routes at ≥24×24. Brand link now 38px computed. |
| **Commit** | `97e1720` |

#### 9. SC 1.4.11 Non-text Contrast — Level AA
| | |
|---|---|
| **Where** | `src/components/Hero.tsx:236` |
| **Failed** | Hero "Guide" CTA border at **1.72:1**; its `white/[0.04]` fill is ~1.1:1, so the border was the only boundary. |
| **Fix** | `border-white/40` = 3.72:1; hover `/40 → /60` to keep the state change visible. |
| **Stated plainly** | WCAG's Understanding text exempts a boundary when the component is identifiable from its text label alone. This label is `#f0f0f0` at 17.78:1, so a reasonable reading is that it **already conformed**. Changed as the conservative position, not as a conceded violation. Container borders (`brand-border`, 1.11:1) are decorative chrome around static content — not UI components — so 1.4.11 does not apply and they are unchanged. |
| **Commit** | `ba9fc41` |

#### 10. SC 2.4.7 Focus Visible — Level AA
| | |
|---|---|
| **Where** | `src/index.css` (global) |
| **Failed** | The audit's usual finding did not apply — **no rule sets `outline: none` anywhere**, so the UA default was technically present. Measuring it told a different story: Chromium renders it as `1px rgb(0,95,204)` — dark blue on a `#060606` page. On the navbar brand link that is effectively invisible. |

## Regression guard

Fixes that are not guarded come back on the next theme update.

Two layers, both gating `deploy.yml` as a hard prerequisite of `build` — a regression fails before the Pages artifact uploads, and coachkettle.com keeps serving the last conforming build:

1. **`eslint-plugin-jsx-a11y`** — static; sees every file including routes no test renders. Rules mapping to findings above escalated from `warn` to `error`.
2. **`axe-core` + Playwright** — dynamic; sees computed colour, layout, and the accessibility tree. 32 assertions × 2 viewports.

Two jsx-a11y defaults are narrowed (not disabled), each documented inline: `no-redundant-roles` permits `role="list"` on `ul`/`ol` (load-bearing for VoiceOver given Tailwind's reset), and `no-noninteractive-tabindex` permits tabindex on `region`/`group` containers. The two linters directly contradict each other on the latter; axe wins, because it describes a real barrier and jsx-a11y describes a code smell.

**Guards proven to bite, not assumed:**

| Injected regression | Result |
|---|---|
| `tabIndex={3}` on a heading | `eslint` exit **1** — `tabindex-no-positive` |
| Hero labels reverted to `white/[0.08]` | `playwright` exit **1** — `color-contrast` |
| Both restored | lint exit **0**, **64/64** passing |

## Corrections made to this audit's own work

Recorded because an audit that hides its own errors is not evidence.

1. **The first test suite passed while testing nothing.** The app uses `HashRouter`; navigating to `/guide` silently served the Home route. All five route tests were scanning the homepage five times. Caught only because `/guide` reported zero `h1` after a fix that was verified present in the bundle.
2. **A contrast "failure" on `/guide` was my measurement error.** axe reported the Tutorial step number at 2.8:1/`#575757` against a computed 3.72:1/`#6a6a6a`. The gap was the `.tutorial-step` fade-in — axe scanned mid-transition at ~81% parent opacity. The suite now settles animations before asserting. The value passes at rest.
3. **A "still failing" target size was a stale server.** A manually-started `npm run preview` was serving an old build that `reuseExistingServer` bound to.
4. **One fix was redundant and was reverted.** `lucide-react` already hides childless icons.
5. **`npm install` failed silently** behind `--silent`, leaving `package.json` unchanged; `eslint@10` conflicts with `eslint-plugin-jsx-a11y`'s `^3–^9` peer. Pinned to `eslint@9` rather than forcing `--legacy-peer-deps`, which would have left the guard broken.
