## Integrated invariants
- The existing `workout_draft_v1` cache remains backward-readable; no additional key or destructive migration. A valid draft is a recoverable in-progress session. Clear-table/delete persist **explicitly empty active rows with original ID/date/parts/createdAt** immediately, cancel pending debounce, and do not erase restoration metadata. Normal empty autosave/background saves use the same production helper.
- All helper reads/writes/removals serialize through one process-local queue. Serialization captures JSON at invocation. A delayed previously accepted write completes before the following clear; failed operations do not poison cleanup. Clear increments a process-local generation immediately. Scheduled callbacks capture that generation, bound to their workout ID across renders; they cannot write after auth/End cleanup. Background saves use a latest-row ref, so clear/delete followed by background in one render cannot repersist the closure's old rows.
- Restore has no same-day deletion policy. Overnight and uncertain older legacy sessions retain exact ID/date/performance/targets/kind/zero evidence; existing session UI allows explicit clear/End/discard before new-session replacement. No invented abandoned TTL. Title uses original date; an explicitly new session refreshes today's title.
- Process-death syncing rows become **committed transport / planned incomplete performance**, with empty actual load/reps and an interruption note. They are editable/deletable, excluded by the existing performed selector, and have a visible notice. New parse ghosts durably retain exact untrimmed composer `pendingInput`; recovery retains that field and embeds it in notes. Older ghosts honestly say original input unavailable. No automatic request/retry, log/PR/rest/End evidence, or fake completion.
- Every normal Start/confirm/template/home/routine-import path waits for restoration. Start paths refuse replacement of the restored active recovery session; routine import may append afterward. Restore read invalidated by clear cannot restore removed data; effect cleanup rejects unmounted callbacks (including React effect replay). Malformed/read-failed drafts stay stored, keep Start locked, and show a recovery warning rather than silently clearing or allowing overwrite.
- Save/clear failures reject with application-owned generic text. HomeScreen shows failure notices; AuthProvider's existing cleanup `attempt` observes rejection. No raw provider/storage payloads are logged. Existing auth cache/sign-out model retained; no new secrets or account namespace migration.
